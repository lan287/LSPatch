## 3. Hook 方法调用开销

**目标**: 每次 Hook 调用额外开销 < 10μs

### 3.1 各回调模式开销

| 回调模式 | 额外开销 | 说明 |
|---------|---------|------|
| BEFORE (空回调) | 2.1μs | 仅进入跳板+返回 |
| AFTER (空回调) | 2.3μs | 进入跳板+调用原方法+返回跳板 |
| BEFORE+AFTER | 3.8μs | 两次跳板穿越 |
| REPLACE (空实现) | 1.2μs | 不调用原方法 |
| REPLACE (调用原方法) | 4.5μs | 手动 invokeOriginal |
| 基准 (无 Hook) | 0μs | 直接方法调用 |

### 3.2 热点路径细项

```
BEFORE 回调时间线 (Android 14, ART_INLINE):
  ├── 进入跳板 (Trampoline Entry)      → 0.3μs
  ├── 参数封装 (HookParam 构造)         → 0.5μs
  ├── 回调执行 (用户代码)               → 用户决定
  ├── 结果回写 (如有 setResult)         → 0.2μs
  └── 返回跳板 (Trampoline Exit)       → 0.3μs
  ─────────────────────────────────────────
  框架总开销 (不含用户代码):             2.1μs
```

### 3.3 1.x vs 2.0 对比

| 场景 | 1.x 平均延迟 | 2.0 平均延迟 | 改善 |
|------|------------|------------|------|
| 空 BEFORE 回调 | 3.5μs | 2.1μs | -40% |
| 空 AFTER 回调 | 3.8μs | 2.3μs | -39% |
| BEFORE+AFTER | 6.2μs | 3.8μs | -39% |
| REPLACE | 4.8μs | 1.2μs | -75% |

> 2.0 通过内联跳板和减少 JNI 跨层调用，显著降低了每帧开销。

## 4. 内存占用

**目标**: 每 Hook 内存 < 1KB

### 4.1 Hook 相关内存分配

| 组件 | 每 Hook 占用 | 说明 |
|------|------------|------|
| 跳板代码 (Trampoline) | 128B | ARM64 32条指令 |
| HookHandle (Java) | 48B | 引用 + 元数据 |
| HookRecord (C++) | 64B | 原地址 + 跳板地址 + 策略标记 |
| HookParam 对象池 | ~96B/对象 | 线程本地缓存复用 |
| **每 Hook 总计** | **~336B** | |

### 4.2 场景内存占用

| 场景 | Hook 数量 | 内存增量 | 说明 |
|------|----------|---------|------|
| 轻量模块 | 10 hooks | ~3.4KB | 典型工具类模块 |
| 中型模块 | 50 hooks | ~16.8KB | 功能增强模块 |
| 重型模块 | 200 hooks | ~67.2KB | 系统定制模块 |

### 4.3 1.x vs 2.0 内存对比

| Hook 数量 | 1.x 内存 | 2.0 内存 | 节省 |
|----------|---------|---------|------|
| 10 | 6.2KB | 3.4KB | -45% |
| 50 | 31.0KB | 16.8KB | -46% |
| 200 | 124.0KB | 67.2KB | -46% |

> 2.0 使用紧凑跳板布局和对象池复用来减少内存开销。

## 9. 性能优化建议

### 9.1 对模块开发者

1. **批量 Hook**: 当一个类需要 Hook 多个方法时，使用 `provider.hookAllMethods()` 而非逐个调用 `hookMethod()`
2. **避免重回调**: BEFORE/AFTER 回调中避免 I/O 和锁竞争
3. **使用 REPLACE 模式**: 完全替换方法时使用 REPLACE 而非 BEFORE (跳过不必要的原方法调用)
4. **及时 unhook**: 不再需要的 Hook 调用 `handle.unhook()` 释放资源

### 9.2 对框架开发者

1. **SuspendAllThreads 批量化**: 合并多次 Hook 操作为一次线程挂起
2. **跳板代码缓存**: 相同签名的跳板代码复用
3. **对象池策略**: HookParam 使用 ThreadLocal 对象池
4. **延迟初始化**: 非关键路径组件延迟到首次使用
